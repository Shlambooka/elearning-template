4a. Text + Media

Plain paragraphs and images. The most common block — use freely.

Any paragraph of explanatory text goes here. Keep it short — one idea per paragraph.

An image can follow. Always include an alt attribute (or alt="" if purely decorative).

<p>Your first paragraph.</p>
<p>Your second paragraph.</p>

<img src="../media/your-image.jpg" alt="Describe what the image shows">

4b. Callout

A highlighted box for tips, key ideas, or warnings. No JS needed.

Key idea

Use callouts to draw attention to the one thing you want the learner to remember from the section.

<div class="callout">
  <h3>Key idea</h3>
  <p>The one thing to remember.</p>
</div>

4c. Accordion

Click-to-reveal panels. Good for letting learners peek at definitions without overwhelming the page.

Content revealed when the trigger is clicked.

Each accordion item is independent.

Important: the id on each panel must be unique on the page, and the trigger's aria-controls must match it. If you copy an accordion into a module that already has one, change the IDs (e.g., panel-neg, panel-pos).

<div class="accordion">
  <div class="accordion-item">
    <button class="accordion-trigger" aria-expanded="false" aria-controls="panel-unique-1">
      Trigger text
    </button>
    <div class="accordion-panel" id="panel-unique-1" hidden>
      <p>Panel content.</p>
    </div>
  </div>
  <div class="accordion-item">
    <button class="accordion-trigger" aria-expanded="false" aria-controls="panel-unique-2">
      Another trigger
    </button>
    <div class="accordion-panel" id="panel-unique-2" hidden>
      <p>Another panel.</p>
    </div>
  </div>
</div>

4d. Tabs

Switch between related content views. Good for comparisons. Keyboard: ←/→ move between tabs, Home/End jump to first/last.

Content shown when the first tab is selected.

Content shown when the second tab is selected.

Important: every id on the buttons and panels must be unique on the page, and each pair must cross-reference correctly (aria-controls on the button → panel id; aria-labelledby on the panel → button id). If you copy tabs into a module that already has them, rename all four IDs.

<div class="tabs">
  <div class="tab-list" role="tablist" aria-label="Describe these tabs">
    <button class="tab-button" role="tab"
            aria-selected="true" aria-controls="tab-panel-1"
            id="tab-1">First tab</button>
    <button class="tab-button" role="tab"
            aria-selected="false" aria-controls="tab-panel-2"
            id="tab-2" tabindex="-1">Second tab</button>
  </div>
  <div class="tab-panel" role="tabpanel"
       id="tab-panel-1" aria-labelledby="tab-1">
    <p>First panel content.</p>
  </div>
  <div class="tab-panel" role="tabpanel"
       id="tab-panel-2" aria-labelledby="tab-2" hidden>
    <p>Second panel content.</p>
  </div>
</div>

4e. Knowledge Check

Multiple-choice with instant feedback. data-answer holds the correct option's value.

Demo question

Which option is correct?

Important: the name on the radio inputs must be unique per quiz on the page. If two quizzes share the same name, selecting one deselects the other. Use name="q1", name="q2", etc.

<div class="quiz" data-answer="b">
  <h3>Question text</h3>
  <p>Optional framing sentence.</p>
  <label class="quiz-option">
    <input type="radio" name="unique-q-name" value="a"> Wrong option
  </label>
  <label class="quiz-option">
    <input type="radio" name="unique-q-name" value="b"> Correct option
  </label>
  <label class="quiz-option">
    <input type="radio" name="unique-q-name" value="c"> Another wrong option
  </label>
  <button type="button" class="quiz-check">Check answer</button>
  <p class="quiz-feedback" role="status" aria-live="polite" hidden></p>
</div>

4f. Module Navigation

Back / Next buttons. Always the last thing before the footer. On the first module, "Back" points to ../index.html; on the last, "Next" points to ../index.html too.

← Previous Next → 
<nav class="module-nav" aria-label="Module navigation">
  <a href="01-intro.html">← Previous</a>
  <a href="03-next.html">Next →</a>
</nav>

4g. Flip Card

Click-to-flip cards. Good for term/definition pairs, or any front/back reveal. Keyboard: Tab to focus, Enter/Space to flip.

Important: the aria-label on each card is what screen readers announce. It should describe what the card reveals — e.g., "Reveal definition of negative feedback". Don't leave it generic.

<div class="flip-cards">
  <button class="flip-card" aria-pressed="false"
          aria-label="Reveal definition of ...">
    <div class="flip-card-inner">
      <div class="flip-card-face flip-card-front">
        <h3>Front title</h3>
        <p class="flip-card-hint">Click to reveal</p>
      </div>
      <div class="flip-card-face flip-card-back">
        <h3>Back title</h3>
        <p>Back content.</p>
      </div>
    </div>
  </button>
</div>

4h. Image Hotspot

Clickable numbered dots on an image that reveal explanations. Only one tooltip open at a time. Keyboard: Tab to each dot, Enter/Space to toggle.

Important: each hotspot's aria-controls must match its tooltip's id (unique on the page). Position is set via inline style="top: X%; left: Y%;".

<figure class="hotspot-figure">
  <img class="hotspot-image" src="../media/your-diagram.jpg"
       alt="Describe the diagram">
  <button class="hotspot" aria-expanded="false"
          aria-controls="tip-1"
          style="top: 25%; left: 30%;">1</button>
  <div class="hotspot-tooltip" id="tip-1" hidden
       style="top: 40%; left: 30%;">
    <p>Explanation.</p>
  </div>
</figure>

4i. Reveal Button

The simplest reveal: click a button, a box appears below. Good for "show the answer" or "reveal an example."

This text was hidden until you clicked the button.

Important: the button's aria-controls must match the content's id. Unique on the page.

<div class="reveal">
  <button class="reveal-button" aria-expanded="false"
          aria-controls="reveal-1">Show the answer</button>
  <div class="reveal-content" id="reveal-1" hidden>
    <p>Hidden content.</p>
  </div>
</div>

4j. Multi-Select Quiz

"Choose all that apply." data-correct is a comma-separated list of every correct option's value. Gives partial-credit feedback.

Demo: select all correct options

Important: every correct value must appear in data-correct exactly once, comma-separated, no spaces needed (but tolerated). Wrong options are any values not listed.

<div class="multiquiz" data-correct="a,c">
  <h3>Question text</h3>
  <label class="multiquiz-option">
    <input type="checkbox" name="mq1" value="a"> Option A
  </label>
  <label class="multiquiz-option">
    <input type="checkbox" name="mq1" value="b"> Option B
  </label>
  <button type="button" class="multiquiz-check">Check</button>
  <p class="multiquiz-feedback" role="status" aria-live="polite" hidden></p>
</div>

4k. Sortable List

Drag items to reorder, or focus an item and press Alt+↑/↓. data-answer on the list is the correct order (comma-separated data-ids). The check/reset buttons and feedback must have IDs matching the list's id + -check, -reset, -feedback.

  1. ⋮⋮ Step A (should be first)
  2. ⋮⋮ Step B (should be second)
  3. ⋮⋮ Step C (should be third)

Important: the list needs an id, and the check button, reset button, and feedback element must each use that id + a suffix: id="mylist-check", id="mylist-reset", id="mylist-feedback". Each item needs a unique data-id matching its position in data-answer.

<ol class="sortable" id="my-list" data-answer="a,b,c">
  <li class="sortable-item" data-id="a">
    <span class="sortable-handle" aria-hidden="true">⋮⋮</span>
    Item A
  </li>
  <li class="sortable-item" data-id="b">
    <span class="sortable-handle" aria-hidden="true">⋮⋮</span>
    Item B
  </li>
  <li class="sortable-item" data-id="c">
    <span class="sortable-handle" aria-hidden="true">⋮⋮</span>
    Item C
  </li>
</ol>
<div class="sortable-actions">
  <button class="sortable-check" id="my-list-check">Check order</button>
  <button class="sortable-reset is-secondary" id="my-list-reset">Reset</button>
</div>
<p class="sortable-feedback" id="my-list-feedback"
   role="status" aria-live="polite" hidden></p>

4l. Timeline

Vertical timeline of steps or events. Pure layout — no JS. Add or remove .timeline-item elements as needed.

  1. Step 1

    What happens first.

  2. Step 2

    What happens next.

  3. Step 3

    And finally this.

<ol class="timeline">
  <li class="timeline-item">
    <span class="timeline-marker" aria-hidden="true"></span>
    <h3>Step 1</h3>
    <p>Description.</p>
  </li>
  <li class="timeline-item">
    <span class="timeline-marker" aria-hidden="true"></span>
    <h3>Step 2</h3>
    <p>Description.</p>
  </li>
</ol>

4m. Dialog

Two-speaker conversation with alternating bubbles. Pure layout — no JS, no interaction. Left = one speaker, right = the other.

Manager

Can we talk about the deadline? I'm worried we're behind.

You

Sure. We lost two days to the review, but we're back on track now.

Manager

Good. Let me know if you need anything to hold the line.

Important: each turn is one .dialog-turn with .is-left or .is-right. Alternate them to show speaker changes. Add as many turns as the conversation needs.

<div class="dialog">
  <div class="dialog-turn is-left">
    <span class="dialog-speaker">Speaker A</span>
    <div class="dialog-bubble">
      <p>What they say.</p>
    </div>
  </div>
  <div class="dialog-turn is-right">
    <span class="dialog-speaker">Speaker B</span>
    <div class="dialog-bubble">
      <p>What they say back.</p>
    </div>
  </div>
</div>

4n. Branching Choice

A prompt and a set of link-options that lead to different outcome pages. Clicking an option stores the choice so it can be marked as "chosen" on the outcome page. The branching itself is in the page structure — each option's href points to a different outcome page.

Demo prompt: what do you do?

Option A (click to mark) Option B Option C

(The links above have href="#" so the demo doesn't navigate. Once you click, the choice is stored — reload the page to see it marked. In a real scenario, each href points to an outcome page.)

Important: every page in a scenario — the scenario page and all its outcome pages — must use the same data-scenario-id, and the same data-choice values, so the "chosen" marker appears consistently. Use a different data-scenario-id for each separate scenario in the course.

Outcome page structure

Outcome pages reuse the standard module skeleton and add one of these:

<div class="branch-outcome is-good">
  <h2>Nice call.</h2>
  <p>This is what happened because of your choice...</p>
</div>

<p><a href="scenario.html">Try again</a> ·
   <a href="next-scenario.html">Next scenario →</a></p>
<!-- On the scenario page: -->
<div class="branch" data-scenario-id="deadline">
  <p class="branch-prompt">Your manager asks about the deadline. What do you do?</p>
  <div class="branch-options">
    <a class="branch-option" data-choice="a"
       href="outcome-a.html">Tell them the truth about the delay</a>
    <a class="branch-option" data-choice="b"
       href="outcome-b.html">Promise to make up the time</a>
    <a class="branch-option" data-choice="c"
       href="outcome-c.html">Ask for more information</a>
  </div>
</div>

Module Page Skeleton

Every module page follows this exact shape. Start a new module by copying an existing one — you don't need to retype this.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Module X: Title — Feedback Loops</title>
  <link rel="stylesheet" href="../css/style.css">
</head>
<body>
  <a class="skip-link" href="#main">Skip to content</a>

  <header class="site-header">
    <p class="module-meta">Module X of Y</p>
    <h1>Module title</h1>
  </header>

  <main id="main">
    <!-- stack blocks here -->
  </main>

  <nav class="module-nav" aria-label="Module navigation">
    <a href="previous.html">← Previous</a>
    <a href="next.html">Next →</a>
  </nav>

  <footer class="site-footer">
    <p>Personal learning project</p>
  </footer>

  <script src="../js/main.js"></script>
</body>
</html>
